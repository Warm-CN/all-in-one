# 社团统一管理系统 - 后端开发指南

后端基于 FastAPI + SQLAlchemy + MySQL，负责认证、RBAC 权限控制、报名、会议室、日程、用户、竞赛队伍与赛事管理。

## 目录结构

```text
app/
├── main.py                 # FastAPI 应用入口、路由注册、CORS、静态 uploads
├── core/
│   ├── config.py           # .env 配置读取与关键配置校验
│   ├── database.py         # SQLAlchemy engine/session
│   ├── dependencies.py     # JWT 身份验证与 RBAC 依赖
│   ├── limiter.py          # SlowAPI 限流器
│   └── security.py         # 密码哈希、JWT 创建与解析
├── api/v1/
│   ├── auth.py             # 登录、注册、个人资料、密码
│   ├── admin.py            # 管理员用户管理，前缀 /api/admin
│   ├── users.py            # 通讯录与个人资料
│   ├── signups.py          # 招新/报名配置与报名数据
│   ├── room_bookings.py    # 日常会议室预约
│   ├── admin_bookings.py   # 管理员会议室统计与导出
│   ├── schedules.py        # 日程查询
│   ├── admin_schedules.py  # 管理员日程管理
│   ├── teams.py            # 竞赛队伍报名、导入、导出、通道配置
│   └── competitions.py     # 赛事、选题、当前赛事配置
├── models/                 # SQLAlchemy 模型
└── schemas/                # Pydantic 请求/响应模型
```

项目根目录的 `main.py` 是本地启动入口，实际 FastAPI 应用对象在 `app/main.py`。

## 本地启动

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .\.venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

编辑 `.env` 后启动：

```bash
python main.py
```

默认地址：

- 后端：`http://localhost:8001`
- Swagger：`http://localhost:8001/docs`
- 健康检查：`http://localhost:8001/health`

首次建库后创建管理员：

```bash
python scripts/init_admin.py
```

默认管理员为 `110 / 654321`，登录后请修改密码。

## 数据库

核心模型：

| 模型 | 表 | 说明 |
|------|----|------|
| `User` | `users` | 用户、角色、账号状态 |
| `SignupConfig` | `signup_configs` | 招新/活动报名配置 |
| `Application` | `applications` | 报名数据与面试阶段 |
| `RoomBooking` | `room_bookings` | 会议室预约 |
| `Schedule` | `schedules` | 日程 |
| `CompetitionEvent` | `competition_events` | 赛事配置 |
| `CompetitionEventTopic` | `competition_event_topics` | 赛事题目 |
| `TopicOption` | `topic_options` | 题库选项 |
| `Team` | `teams` | 竞赛队伍 |
| `TeamMember` | `team_members` | 队员 |
| `TeamChannelConfig` | `team_channel_configs` | 报名/选题/修改通道 |
| `InspectionAssignment` | `inspection_assignments` | 验收安排 |

应用启动时会执行 `Base.metadata.create_all(bind=engine)`，适合空库首次创建表。它不会自动修改已有表结构；已有生产库升级前应先备份，再按迁移脚本或手动 SQL 校验字段差异。

`scripts/rebuild_database.py` 会删除所有表，仅用于开发环境重置。

## 认证与权限

认证使用 Bearer Token：

```http
Authorization: Bearer <access_token>
```

权限依赖位于 `app/core/dependencies.py`：

| 依赖 | 含义 |
|------|------|
| `get_current_user` | 校验 JWT 并返回用户 |
| `get_current_active_user` | 要求用户状态为 `active` |
| `require_member` | `member` 或 `admin` |
| `require_admin` | 仅 `admin` |
| `RoleChecker([...])` | 自定义角色集合 |

登录与注册接口有限流：

- `POST /api/v1/auth/login`：`5/minute`
- `POST /api/v1/auth/register`：`3/minute`

## 接口概览

| 模块 | 关键路径 | 权限 |
|------|----------|------|
| 登录 | `POST /api/v1/auth/login` | 公开 |
| 注册 | `POST /api/v1/auth/register` | 公开，注册后待审核 |
| 当前用户 | `GET /api/v1/auth/me` | 登录用户 |
| 修改密码 | `PUT /api/v1/auth/password` | 登录用户 |
| 管理员重置密码 | `POST /api/v1/auth/reset-password` | Admin |
| 管理员用户管理 | `/api/admin/users...` | Admin |
| 通讯录 | `GET /api/v1/users/` | 登录用户 |
| 更新个人资料 | `PUT /api/v1/users/me` | 登录用户 |
| 报名配置/提交 | `/api/v1/signups/...` | 公开 + Member/Admin + Admin |
| 会议室预约 | `/api/bookings...` | 登录用户 |
| 管理员会议室导出 | `/api/v1/admin/bookings/export` | Admin |
| 日程查询 | `GET /api/v1/schedules` | 登录用户 |
| 管理员日程 | `/api/v1/admin/schedules...` | Admin |
| 竞赛队伍 | `/api/v1/teams...` | 公开 + Member/Admin + Admin |
| 赛事管理 | `/api/v1/competitions...` | 公开 + Admin |

## 响应格式

业务接口统一返回：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

错误响应同样使用 `{code, msg, data}`，部分 FastAPI/Pydantic 校验错误仍会返回标准 `detail`。

## 开发约定

- 新增路由优先放在 `app/api/v1/`，并在 `app/main.py` 注册。
- 新增受保护接口时使用 `Depends(require_member)` 或 `Depends(require_admin)`。
- 新增模型后确认 `app/models/__init__.py` 已导入，否则 `create_all` 和 Alembic metadata 可能看不到模型。
- 涉及生产库结构变化时，不依赖 `create_all` 修改已有表，先写迁移或明确 SQL。
- 上传文件统一经过 `/uploads` 暴露，生产环境要保证项目根目录下 `uploads/` 可写。
