# 拓竹杯打印机预约：实施与验收

## 当前业务规则

1. 复用现有 `competition_events` 和 `teams`，打印机模块绑定对应拓竹杯赛事的 `module_key`。不创建独立打印队伍，不提供登记接口、队伍口令或邀请码。
2. 公开页面仅输入队长学号查询。只有绑定赛事内有效队伍的队长学号能查到并预约；队员学号、其他赛事队长学号、已取消或申请删除队伍不能预约。
3. 没有队伍的同学跳转 `/team-portal?event_id=对应赛事ID`，在已有赛事报名页报名。跳转必须选中对应赛事，不能被浏览器此前选择的其他赛事覆盖。
4. 三台机各自独立校验 `[开始, 结束)` 冲突，同队可以在同一时段同时预约三台。符合时间与设备规则立即成功，不进入审批。
5. 管理员直接添加或删除预约，无需批准队伍申请。添加遵守机器冲突与时间规则；删除取消占用并保留操作人、原预约和异常历史。
6. 保留签到、归还、上一实际使用队伍追溯及异常维护流程。只限制已启用开放规则下的开始时间，结束可跨夜。
7. 增量迁移兼容上一版独立队伍表和预约，不删除历史、不把相同数字的旧队伍ID误认为现有队伍ID。

## 验收案例

| 编号 | 操作/场景 | 期望 |
|---|---|---|
| T01 | 输入拓竹杯有效队长学号 | 返回现有队伍及本队预约，仅输入学号即可 |
| T02 | 输入队员学号、其他赛事队长学号、不存在学号 | 无可预约队伍，不创建任何队伍 |
| T03 | 原队伍取消、申请删除或切换绑定赛事后使用旧会话 | 拒绝预约 |
| T04 | 访问旧 `/printers/teams` 登记接口 | 不存在；页面无登记、口令、邀请码和审批 |
| T05 | 点击对应报名入口，已有其他赛事浏览器选择 | 仍选中URL指定的赛事 |
| T06 | 同一队伍预约三台同一时间段 | 三条立即成功 |
| T07 | 同机相同、部分交叠、包含和被包含 | 拒绝 |
| T08 | 同机结束与后条开始相等 | 允许 |
| T09 | 两会话并发抢同机同段 | 一条成功、一条冲突 |
| T10 | 过去时间、结束不晚于开始、无效日期 | 拒绝 |
| T11 | 启用办公室时间，开门/关门边界与非办公日 | 只开始受约束；关门开始拒绝，结束可跨日 |
| T12 | 未查询或其他队伍操作本队预约 | 拒绝 |
| T13 | 取消未来预约后再约同段 | 允许，原历史保留 |
| T14 | 签到前、实际使用中、归还后状态切换 | 合法操作成功，重复和提前操作拒绝 |
| T15 | 上队未归还，下队签到 | 拒绝同时使用 |
| T16 | 实际上队使用后下队报告异常 | 锁定上队使用快照，机器维护；未使用/未来/取消不误追溯 |
| T17 | 无上一使用记录报告异常 | 明确无历史，不猜测队伍 |
| T18 | 管理员直接添加当前拓竹杯队长预约 | 立即成功，冲突时拒绝 |
| T19 | 管理员删除未来或使用中预约 | 释放占用，记录操作人并保留使用和异常历史 |
| T20 | 普通用户或打印队伍会话访问管理API | 拒绝 |
| T21 | 管理员恢复仍有未处理异常的设备 | 拒绝，处理后可恢复 |
| T22 | 空库初始化两次 | 恰好三机，不创建打印专属队伍表 |
| T23 | 上一版数据库执行迁移两次 | 历史保留，唯一匹配现有队伍才绑定，未匹配记录不冒认归属 |
| T24 | 新旧队伍数字ID相同但学号/赛事不同 | 不会把旧预约分配给错误现有队伍 |
| T25 | 手机和桌面查询、预约、取消、管理员增删 | 布局可用，无JS异常 |
| T26 | 最终生产包与同源API、深层页面刷新 | 页面和接口可用 |

本表是验收范围，实际自动测试与浏览器执行结果见部署指南。
