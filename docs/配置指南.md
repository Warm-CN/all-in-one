# 社团统一管理系统 - 配置指南

本文档说明本地开发与生产部署共用的关键配置。完整服务器部署流程见 [DEPLOY.md](DEPLOY.md)。

## 环境要求

| 组件 | 建议版本 |
|------|----------|
| Python | 3.10+ |
| MySQL | 8.0+ |
| Node.js | 18+ |
| npm | 9+ |

## 后端配置

### 1. 安装依赖

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .\.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. 创建数据库

```sql
CREATE DATABASE club_management CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

生产环境建议使用独立数据库用户：

```sql
CREATE USER 'club_user'@'localhost' IDENTIFIED BY 'replace_with_strong_password';
GRANT ALL PRIVILEGES ON club_management.* TO 'club_user'@'localhost';
FLUSH PRIVILEGES;
```

### 3. 配置 `.env`

复制示例文件：

```bash
cp .env.example .env
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

关键配置如下：

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=club_user
DB_PASSWORD=replace_with_strong_password
DB_NAME=club_management
DB_ECHO=False

SECRET_KEY=replace_with_random_secret
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=1440

DEBUG=False
APP_NAME=社团统一管理系统
APP_VERSION=1.0.0

BACKEND_CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

生成 `SECRET_KEY`：

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

注意：

- `DB_PASSWORD` 不能为空。
- `SECRET_KEY` 不能为空，也不能使用默认占位值。
- 生产环境使用 `DEBUG=False`。
- 如果前端和后端由同一个 Nginx 域名提供服务，`BACKEND_CORS_ORIGINS` 可以保留域名来源；同源请求通常不会触发跨域。

### 4. 初始化数据

应用启动时会根据 SQLAlchemy 模型自动创建缺失的数据表。首次部署后建议创建管理员账号：

```bash
python scripts/init_admin.py
```

默认管理员：

| 字段 | 值 |
|------|----|
| 学号 | `110` |
| 密码 | `654321` |

`scripts/rebuild_database.py` 会删除全部现有表，仅用于开发环境重置数据。生产环境不要运行该脚本，除非已经完成备份并明确接受数据清空。

### 5. 启动后端

开发模式：

```bash
python main.py
```

或：

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001 --reload
```

访问地址：

- API 文档：`http://localhost:8001/docs`
- ReDoc：`http://localhost:8001/redoc`
- 健康检查：`http://localhost:8001/health`

## 前端配置

### 1. 安装依赖

```bash
cd frontend
npm install
```

### 2. 开发环境

开发环境一般不需要创建 `.env`。`vite.config.js` 已配置代理：

```js
server: {
  port: 3000,
  proxy: {
    '/api': {
      target: 'http://localhost:8001',
      changeOrigin: true
    }
  }
}
```

启动：

```bash
npm run dev
```

访问 `http://localhost:3000`。

### 3. 生产环境

生产环境由 Nginx 同源代理 `/api` 到后端，构建前创建 `frontend/.env.production`：

```env
VITE_API_BASE_URL=
```

然后构建：

```bash
npm run build
```

构建产物在 `frontend/dist`。

## 常见问题

### 后端启动时报 `DB_PASSWORD` 或 `SECRET_KEY` 错误

检查 `.env` 是否在项目根目录，变量是否为空，`SECRET_KEY` 是否仍为示例占位值。

### 前端请求到了 `localhost:8001`

说明生产构建时没有设置 `frontend/.env.production`。创建该文件并写入 `VITE_API_BASE_URL=` 后重新 `npm run build`。

### 数据表缺字段

先备份数据库，再对照当前模型与 Alembic 脚本处理。当前项目启动会自动创建缺失表，但不会自动修改已有表结构。
