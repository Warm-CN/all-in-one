# 第三阶段：竞赛队伍模块开发文稿

## 1. 背景与目标

在现有 FastAPI + SQLAlchemy + Alembic + Vue3 的架构内，建设“竞赛队伍报名与选题管理”能力，当前阶段重点目标如下：

- 公开端：游客可报名、查询、修改本队信息与选题。
- 内部端：成员可查询并下载数据。
- 管理端：管理员可进行通道开关控制、批量操作、导出、验收安排与赛事配置。
- 数据隔离：不同比赛间报名信息不冲突（按 `module_key` 隔离）。
- 统计可视化：已结束比赛展示队伍数、报名人数和各选题报名数量。

本阶段已从“模型落地”推进到“接口与页面联调可用”，并完成关键业务规则修订。

## 2. 角色权限边界（已确认）

- Visitor：仅允许公开报名、修改本队选题与信息、查询信息。
- Member：允许查询报名信息、下载数据。
- Admin：允许全部操作，包括报名/选题通道开关、队伍信息维护、选题调整、验收分配、导出、比赛状态切换与名称配置。

## 3. 数据模型与规则（当前实现）

### 3.1 题库表 `topic_options`

- 用途：维护可选题目列表与可用状态。
- 关键字段：`code`、`title`、`description`、`is_active`、`max_teams`。

### 3.2 队伍主表 `teams`

- 用途：保存队长信息、队伍信息、当前选题。
- 关键字段：
  - 队伍信息：`team_name`、`competition_track`、`status`
  - 队长信息：`captain_name`、`captain_student_id`、`captain_phone`
  - 比赛归属：`module_key`
  - 选题信息：`topic_id`
- 规则：`captain_student_id` 不再做全局唯一约束，改为在业务层按 `module_key` 校验唯一。

### 3.3 队员表 `team_members`

- 用途：保存队员明细（不含队长）。
- 关键字段：`team_id`、`name`、`student_id`、`phone`、`email`、`college`、`major_class`。
- 规则：`student_id` 不再做全局唯一约束，改为在业务层按 `module_key` 校验不重复。

### 3.4 通道配置表 `team_channel_configs`   

- 用途：控制报名通道与选题通道状态。
- 关键字段：`module_key`、`signup_open`、`topic_open`、`info_update_open`、`signup_close_at`、`topic_close_at`、`info_update_close_at`。
- 约束：`module_key` 唯一，便于按模块读取配置。

### 3.5 验收安排表 `inspection_assignments`

- 用途：记录每支队伍的验收时间地点与备注。
- 关键字段：`team_id`、`first_*`、`second_*` 双阶段验收字段，并兼容旧字段。
- 约束：`team_id` 唯一，确保一队一条当前安排。

### 3.6 比赛活动与选题映射

- 比赛主表：`competition_events`（`cup_type`、`name`、`module_key`、时间窗口、`is_current` 等）。
- 比赛选题映射：`competition_event_topics`（比赛下选题、文档、题库映射）。
- 业务规则：
  - 允许全部比赛均为“非进行中”（即当前无比赛）。
  - 设为“进行中”时会自动将其他比赛置为非进行中。

## 4. 迁移策略

- 使用 Alembic 增量迁移，覆盖：
  - 竞赛相关模型建表。
  - 通道与报名字段扩展。
  - 学号索引从全局唯一调整为普通索引（支持跨比赛重复学号）。
- 注意：索引调整后需执行 `alembic upgrade head` 以确保数据库状态与代码一致。

## 5. 关键接口与页面行为（已落地）

### 5.1 公开端（`/team-portal`）

- 报名：按当前进行中比赛的 `module_key` 入库。
- 修改选题：改为“先查队伍（学号）再选题提交”，且仅需队长学号校验。
- 队伍查询/修改：支持按学号检索并修改本队信息。

### 5.2 管理端赛事中心（`CompetitionCenter`）

- 新建比赛、维护报名页标题、维护选题、切换进行中状态。
- 历史卡片展示：队伍数、报名人数、选题数量。
- 已结束比赛追加统计：按选题显示“队伍数/人数”。

### 5.3 队伍管理页（`TeamsCenter`）

- 从赛事中心进入：携带 `module_key` 管理对应比赛。
- 直接进入队伍管理页：自动定位当前进行中比赛；若无则提示“没有正在进行的比赛”。
- 管理员可在该页修改比赛名称。

## 6. 当前业务规则摘要

1. 报名、修改、查询均以 `module_key` 作为比赛隔离维度。
2. 同一学号可在不同比赛报名，但同一比赛内不可重复。
3. 比赛可以全部不进行（当前无比赛）。
4. 选题数量不设比赛级上限，可按需新增。
