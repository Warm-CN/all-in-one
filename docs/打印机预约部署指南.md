# 拓竹杯打印机预约：自动开始、自动结束与五台设备发布

## 本次更新范围

公开入口 `/printer-booking`，管理员入口 `/admin/printers`。预约成功后无需二次验证、签到或确认开始，也不会因未确认而超时取消。到达开始时间自动进入“使用中”，到达结束时间自动完成并释放占用；仍支持开始前主动取消、使用期间提前归还和报告设备异常。

这里的自动开始、结束指预约状态和时段占用，不包含对实体打印机下发打印、开机、停机或断电指令。后端每 15 秒持久化同步状态，接口访问时也会同步；页面每秒按预约起止时间更新状态，不需要手动刷新。自动变更不伪造签到、归还时间，保留原有使用和异常历史。

当前开放五个独立预约位：五山 A1 多色（ID 2）、五山 X2D（ID 3）、大学城 A1（ID 4）、大学城 A2 单机（ID 5）、大学城 A2L 多色（ID 6）。五山 A1 单色（ID 1）下架，配置接口直接过滤旧库中的该设备，队伍及管理员均不能新增预约或恢复它。其历史设备行、预约和异常记录保留，ID 不重排；已有预约不擅自转移到其他设备。管理员可按实际情况处理该设备尚未开始的旧预约。

单次预约最长 8 小时，正好 8 小时允许，超过则拒绝；队伍和管理员执行相同校验。每天可开始的时段仍为北京时间 09:00–12:00、14:00–17:00、19:00–21:30，各段包含开始时刻、不包含截止时刻。结束时间可以跨夜。同队可以同时预约不同设备，同机时间不能重叠。

**从已部署的“最长预约 8 小时”版本升级，本次需要更新后端和前端，不需要数据库迁移，不需要运行 `python -m scripts.init_printers`。** 旧库即使仍有六条设备记录，更新代码后也只开放五台。

在本地 PowerShell 中执行：


## 2. 本地 Windows：在 E 盘构建、打包并上传前端

为把依赖下载、缓存和构建产物放在 E 盘，从现有 D 盘项目导出已提交的前端源码到一个新的 E 盘发布目录，再安装依赖和构建。必须先完成第 0 步的提交和推送；只构建当前提交，避免夹带工作区其他未提交页面改动。服务器不需要构建前端。将 `服务器公网IP` 替换为实际地址；SSH 用户和端口如有不同，按实际配置修改。

在本地 PowerShell 中执行下面整段：

```powershell
& {
$ErrorActionPreference = "Stop"
$serverHost = "服务器公网IP"
$releaseId = (Get-Date -Format "yyyyMMdd-HHmmss") + "-" + [guid]::NewGuid().ToString("N").Substring(0, 8)
$releaseRoot = Join-Path "E:\all-in-one-deploy" $releaseId
$buildDir = Join-Path $releaseRoot "frontend"
New-Item -ItemType Directory -Path $releaseRoot -Force | Out-Null
$sourceArchive = Join-Path $releaseRoot "frontend-source.tar"

# 直接导出已提交版本；使用输出文件参数，避免 PowerShell 管道损坏二进制归档。
git -C "D:\SCUT-wuxie-code\all-in-one" archive --format=tar --output $sourceArchive HEAD frontend
if ($LASTEXITCODE -ne 0) { throw "导出前端源码失败，请停止发布" }
tar -xf $sourceArchive -C $releaseRoot
if ($LASTEXITCODE -ne 0) { throw "解压前端源码失败，请停止发布" }
Set-Location $buildDir

# 依赖和 npm 缓存都写入 E 盘；显式安装构建所需的 Vite 等开发依赖。
npm ci --include=dev --cache "E:\all-in-one-deploy\npm-cache"
if ($LASTEXITCODE -ne 0) { throw "安装前端依赖失败，请停止发布" }

$previousApiBase = $env:VITE_API_BASE_URL
try {
    $env:VITE_API_BASE_URL = "/api"
    npm --cache "E:\all-in-one-deploy\npm-cache" run build
    if ($LASTEXITCODE -ne 0) { throw "前端构建失败，禁止继续上传" }
} finally {
    # 恢复当前终端原有配置，避免影响其他项目。
    if ($null -eq $previousApiBase) {
        Remove-Item Env:VITE_API_BASE_URL -ErrorAction SilentlyContinue
    } else {
        $env:VITE_API_BASE_URL = $previousApiBase
    }
}

if (!(Test-Path -LiteralPath ".\dist\index.html" -PathType Leaf)) { throw "缺少 dist/index.html" }
if (!(Test-Path -LiteralPath ".\dist\assets" -PathType Container)) { throw "缺少 dist/assets" }

# 只对本次构建结果打包，不复用原项目中的旧压缩包。
tar -czf printer-dist.tar.gz -C dist .
if ($LASTEXITCODE -ne 0) { throw "前端打包失败" }
scp .\printer-dist.tar.gz "root@${serverHost}:/tmp/all-in-one-printer-dist.tar.gz"
if ($LASTEXITCODE -ne 0) { throw "上传失败，请勿切换服务器页面" }
Write-Host "前端已上传；本次构建目录：$buildDir"
}
```

`npm run build` 必须出现 `built in ...` 且退出成功，才会继续打包上传。`npm ci --include=dev` 在新目录安装构建依赖，可避免缺少 `vite`。这段命令不修改原项目的依赖目录，也不使用原项目中已存在的 `frontend/printer-dist.tar.gz`。

## 3. 云服务器：检查并切换前端

确认 Nginx 静态根目录为 `/var/www/all-in-one/frontend/dist`。上传成功后，回到服务器 SSH 终端执行整段。先解压和检查新文件，再移动旧目录；新目录切换失败时恢复旧目录。

```bash
(
    set -e
    cd /var/www/all-in-one/frontend
    test -f /tmp/all-in-one-printer-dist.tar.gz

    NEW_DIR=$(mktemp -d /var/www/all-in-one/frontend/dist-next-XXXXXX)
    tar -xzf /tmp/all-in-one-printer-dist.tar.gz -C "$NEW_DIR"
    test -s "$NEW_DIR/index.html"
    test -d "$NEW_DIR/assets"
    chmod -R a+rX "$NEW_DIR"
    sudo nginx -t

    # 使用随机后缀避免覆盖同秒内产生的旧版本备份。
    BACKUP_DIR="dist-before-auto-booking-$(date +%Y%m%d-%H%M%S)-${NEW_DIR##*-}"
    if [ -e dist ] || [ -L dist ]; then
        mv dist "$BACKUP_DIR"
    fi

    if mv "$NEW_DIR" dist; then
        echo "新版前端已发布；若存在旧版，保存在：$BACKUP_DIR"
    else
        if { [ -e "$BACKUP_DIR" ] || [ -L "$BACKUP_DIR" ]; } && [ ! -e dist ] && [ ! -L dist ]; then
            mv "$BACKUP_DIR" dist
        fi
        echo "发布失败，已尝试恢复旧版"
        exit 1
    fi
)
```

沿用现有 Nginx 配置时，只替换静态文件无需重启或重新加载 Nginx。浏览器发布后按 `Ctrl+F5` 强制刷新。已有 `/api` 反向代理应继续转发到 `127.0.0.1:8001`，不要把 API 请求指向访问者的 `localhost`。

## 4. 上线检查

1. 打开 `/printer-booking`，确认五山只有 A1 多色和 X2D，全站共五台；管理页也只有五台可操作设备。
2. 查询有效队长学号，提交未来预约。预约成功后无需再次验证，不出现“确认开始”按钮。
3. 到开始时间显示“使用中”，保持页面打开也会更新；超过旧确认宽限时间仍占用设备，不会自动取消。
4. 到结束时间显示“已结束”并释放预约占用；仍可在开始前主动取消，使用期间可提前归还。
5. 队伍和管理员均不能提交超过 8 小时的预约；开始时段限制、同机冲突检查保持生效。
6. 旧设备的历史预约、异常仍可查看，名称显示“（已下架）”。已有旧设备预约需要调整时，由管理员核实后处理。

后端出现问题时查看：

```bash
sudo journalctl -u club-backend -n 100 --no-pager
```

健康检查仅说明服务已启动，自动流转还需要结合预约状态和日志确认。
